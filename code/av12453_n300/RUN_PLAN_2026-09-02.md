# Plan: |Av_n(12453)| for n <= 300 (computation only; not for the paper)

Date: 2026-09-02.  Status: campaign RUNNING on this machine (Lima VM on the
author's Mac, 8-CPU quota, 16 GB), started 20:35 UTC.

## Algorithm and engine (v1, frozen for this campaign)

Engine: `engine/av12453_gemm_split.cpp` (sha256 a617f2dc...; copy kept as
`campaign/av12453_gemm_split.cpp.used`).  It evaluates the proved reduced
recurrence (paper Section 7) with the proved homogeneous split
(notes/av12453_speedup_proofs.tex) exactly as the certified engine
`code/av12453_homog_split.cpp` does, but the split is a dense GEMM per grade
and evaluation point, with 16-bit primes and u16 storage so that no modular
reduction happens inside the kernel (all products and sums exact in
binary64), degree-aware point pruning (rows q <= W-2-j), OpenMP over points.

Measured here (8 threads, `--prune`): N=150 4.6 s / 0.42 GiB; N=200 23.5 s /
1.3 GiB; N=300 199 s / 6.5 GiB per prime (u16, p=65521).  The u32 build
(primes below 2^21) needs 10.5 GiB with `--spill` and 225 s per prime.
GEMM throughput 2.2e10 multiply-adds per second per thread (3.9x the old
engine's kernel); whole-run speedup over the old engine 4.6x at N=200 on 8
threads with half the memory.  The empty-stack phase is still serial (about
32% of the N=300 time); engine v2 (in progress in `engine_v2/`) parallelizes
it and is expected to bring N=300 to about 145 s per prime.

## Prime set and reconstruction

B_300 = sum_m C(300,m)^2 |Av_m(1342)| has 1136 bits (B_150 has 558, as in
the paper).  `harness/primes_u16.txt`: the 77 largest primes below 2^16,
of which 71 suffice for the CRT bound and 6 are withheld as checks.
Reconstruction: `harness/reconstruct.py` (exact bound from Bona's series,
CERTIFY of every file for n <= 150, CRT from the primary set, withheld-prime
agreement, output `terms_0_300.txt` with "n a_n" lines).

## Running it

    # build one binary per prime (about 1.2 s each)
    cat harness/primes_u16.txt | xargs -P 8 -I{} sh -c 'g++ -O3 -march=native -std=c++17 -fopenmp -funroll-loops -DMODP={}ull engine/av12453_gemm_split.cpp -o campaign/bin/av12453_gemm_{}'
    # resumable sweep, one prime at a time, 8 threads
    bash harness/run_all.sh --bindir campaign/bin --primes harness/primes_u16.txt --n 300 --threads 8 --outdir campaign/residues --extra-args "--prune"
    # afterwards
    pypy3 harness/reconstruct.py --residues-dir campaign/residues --n 300 --output campaign/terms_0_300.txt

Each prime writes `campaign/residues/<prime>.txt` when complete (a .tmp file
while running); re-running the sweep skips completed primes.  A completed
file that is well formed but wrong would be skipped too, which is why the
six withheld primes are essential: a wrong file is caught at reconstruction
(and for n <= 150 by CERTIFY).
